# LLM Translator — Blue Lemonade integration

Modified 2026-09-24. Based on the existing local 2.1.6 modification of https://github.com/NamelessKkang/llm-translator-custom (original: https://github.com/1234anon/llm-translator). Original AGPL-3.0 LICENSE retained. Host import paths and asset loading adapted; one settings view can appear in the extension drawer or Blue Lemonade; existing storage keys retained.
Modified 2026-10-10 (2.3.0): added translateForSpeech / speechReady / speechModelTag to the Blue Lemonade translator API (speech-translate.js, glossaryLinesFor) so the bundled TTS add-on can read lines in a chosen listening language with this translator's connection; chat translation behaviour unchanged.
Modified 2026-10-10 (2.3.1): translation-segments.js remembers the source-echo comparison key of each text for the rest of the current task (cleared on the next microtask), so end-of-reply echo checks no longer re-normalise the same paragraphs and sentences; results unchanged.
Modified 2026-10-12: protected blocks registered at runtime through the Blue Lemonade translator API (protect / unprotect, memory only, appended after the user's protected-text rules) are never sent to the model and are kept in place once; a protected block whose placeholder the model drops is put back at its source paragraph and that result is not cached; fold views show such blocks only on the translated side; a queued auto translation whose message text changed during the short wait is translated with the current text instead of being skipped; a document event llm-translator:rendered is sent after the translator redraws a message; reuse checks ignore protected blocks when rejecting HTML.
Modified 2026-10-13: a translation that is mostly Korean/Japanese/Chinese drops a line holding only one Latin-script word that appears nowhere in the source text (a model glitch seen as a stray place name on its own line); applied before caching, to cached rows from earlier versions, to /llmTranslate results and to stored translations when shown; a translation the user edited by hand is marked (extra.translation_edited = source hash) and left alone. Modified 2026-10-13 (6.2.5): the same filter also removes paragraph-marker debris when the source has no ⟦ ⟧ — a Latin-only aside ending in ⟧ at the start of a line, and leftover ⟦n⟧ markers.

Modified 2026-10-15: automatic incoming/outgoing translation is queued after awaited message-render and saved-swipe events and their postprocessors finish. Valid saved-swipe translations retain the existing cache skip. Nested renders of one message are coalesced; chat changes, swipe changes, failed dispatches and stopped observers discard pending work. The host emitter keeps its original return value, receiver and errors. Existing source/edit/display guards remain active from queueing onward; throttled jobs recheck their target after waiting.

Modified 2026-10-15: known prompt status/header/footer cards translate display values while preserving renderer keys, markup, hidden data and code locally. Explicit protected-text rules keep precedence. Missing, duplicated or reordered field tokens reject the result; card structures stay outside later prose cleanup and render once on the translated side of combined views. Existing cache rows whose card keys or code differ from the source are skipped during reuse without deleting stored rows; valid untranslated cards remain eligible and can be explicitly retranslated.

Modified 2026-10-15: optional automatic reference-history selection measures the final request messages after prefill and reply settings are resolved. Existing manual counts and manual send-reference clipping remain unchanged. Auto uses complete recent messages, native chat-completion token counting, context-change guards, and explicit failures for unsupported/unmeasured request types. The default remains manual with five messages.

Modified 2026-10-15: the thinking blocks of the Fruit and Deus prompt presets (an <ECoT> block, a thought that opens the reply without its start tag and ends with </ECoT> or </thinking> before the story, and <scene_plan>/<scene_reasoning>) are protected like <think>: never sent and kept in place in the original language. Story text, inner thoughts and status cards are translated as before. The new rules come after the existing built-in ones, so replies without these blocks keep their placeholder numbers and paragraph cache keys.

Modified 2026-10-15: when the chat translation prompt targets Korean, fixed status card values (dates, weekdays, times of day, values made only of known weather words) are filled locally by rule (card-values.js), and a card value the model translated before is reused from a bounded local memory (latest 400, per chat prompt and glossary scope, localStorage on this device). Such values are never sent to the model. Retranslation does not read the memory and overwrites it with the new result; half-translated, unchanged or placeholder answers are not remembered; input translation and other target languages are unchanged.

Modified 2026-10-17 (2.7.9): when the chat translation prompt targets Korean, paragraphs that are already Korean and Korean quoted dialogue inside mixed paragraphs are not sent to the model. They are replaced by the same [[__VAR_n__]] placeholders as protected blocks and restored byte for byte after the reply (korean-keep.js); a message that is all Korean makes no request. New setting "이미 한국어인 부분은 보내지 않기" (keep_korean_source, on by default). Retranslation, input translation and other target languages are unchanged.

Modified 2026-10-17 (2.8.0): the help text of the "이미 한국어인 부분은 보내지 않기" setting now names straight double quotes (" ") next to 「」 as kept Korean dialogue. No behaviour change.

Modified 2026-10-18 (2.8.1): the default Max Response Length of the Google and Vertex AI direct connections is 4000 instead of 1000. A saved value of exactly the old default 1000 is raised to 4000 once (gemini_length_707); other saved values are kept. With 1000 a long message was split into many 1200-character requests, each carrying the prompt and context again. The five Max Response Length labels now explain this in a tooltip.

Modified 2026-10-18 (2.8.2): with "자동 · 현재 컨텍스트" the reply share kept free while choosing recent messages is capped at 8192 tokens (AUTO_REPLY_RESERVE_MAX = THINK_MIN_TOKENS in context-auto.js). One translation reply never exceeds one bundle (3600 characters, about 3000 tokens) and thinking models already get an 8192 output floor, so a large Max Response Length such as 100000 no longer leaves no room for context. The max_tokens sent in the request is unchanged.

Modified 2026-10-18 (2.8.3): the translation bundle size follows the response length only: Max Response Length × 1.2 characters, at least 400, without the former 3600-character ceiling (3600 when the limit is unknown). The paragraph bundles, the speech translation bundles and the whole-or-chunks decision use the same limit. The cut-short safety (halving a bundle whose reply stops mid-sentence) is unchanged. With "자동 · 현재 컨텍스트" the reply share is min(Max Response Length, max(8192, request characters ÷ 1.2)).

Modified 2026-10-18 (2.9.0): the progress label above a message and the in-progress preview follow the message through the translation guard, so they stay after the same chat is reloaded in place (the message becomes a new object); the "번역이 이미 진행 중입니다" notice names the message and how many seconds it has been running. When a streamed bundle stops (connection lost, stop, timeout, 429, failure), paragraphs already closed in a reply numbered from ⟦0⟧ are kept for one day under resume: keys in the paragraph store (not the 30-day cache), checked like the cache; translating again sends only the remaining paragraphs.

Modified 2026-10-18 (2.9.1): the whole-message path (used when the paragraph cache is off, e.g. the retranslate button, and since 2.8.3 for most messages) streams its single request: paragraphs closed by a blank line are previewed as they arrive and the progress label shows paragraph n/total. When that request stops, the leading paragraphs that line up with the source paragraphs (placeholders, dialogue quotes, length, no refusal or failure mark) are kept as a one-day checkpoint and translating again sends only the remaining paragraphs.

Modified 2026-10-18 (2.9.2): the paragraph-cache path now keeps the paragraphs closed while streaming when the bundle fails. A failed bundle is reported once more as all nulls at its end; that last report used to replace the closed paragraphs, so nothing was kept after a timeout or a dropped connection. Later reports now only add received text.

Modified 2026-10-18 (2.9.3): a streamed translation is no longer cut after a fixed 90 seconds while text keeps arriving. The first text may take the request time limit (90 s + 10 ms per response token, up to 10 minutes); after that the limit restarts with every piece and stops the request only after 90 seconds without new text (direct connection: STREAM_IDLE_MS in streamedReply; current connection: touch in current-connection.js). Non-streamed requests use the same response-sized limit.

Modified 2026-10-18 (2.9.4): a Han character sitting inside a Korean word (Hangul on both sides, e.g. 특注품 for 特注品) is treated as a leftover even when it is a single character or not in the source, so the line is sent again with the kanji fix note and the paragraph is not cached. Han characters from a Korean source line, glossary forms and intentional spans (parentheses, quotes, readings) are kept; hanja followed only by a particle (會議에) stays as before.

Modified 2026-10-18 (2.9.5): preserve the visible paragraph and its reading position when translation previews or final text change the message height. Follow new text only when already at the bottom; user scrolling cancels pending layout corrections.

Modified 2026-10-18 (2.9.6): remember a manually corrected name or term for the current chat from the existing selection tool. Validate the source term locally, preserve the selected occurrence, and support undo and removal. Chat rules override broader glossary scopes without additional model calls; cache ownership and asynchronous save verification keep other chats isolated.

Modified 2026-10-18 (2.9.7): add current-chat character speech preferences for explicitly identified speakers and optional addressees, with local management and undo. Reuse existing translation checks in a read-only review list; any repair targets an explicitly chosen item and validates current message, chat, and policy state. Listing and saving preferences do not request model responses.

Modified 2026-10-18 (2.9.8): expose current-chat speech preferences directly in translator settings without a selection toggle. Explain precedence and overlapping speech rules. Add explicitly requested paragraph candidate comparison (natural, close to source, and speaker voice), with alignment and request-attempt counts, cancellation, manual application and guarded undo. Candidate edits stay in the current chat and preserve unknown save outcomes.

Modified 2026-10-20 (Blue Lemonade 7.3.1): the paragraph cache now covers replies of up to 401 paragraphs (801 split parts; it stopped at 81 paragraphs, so longer replies went as one whole-text request and a one-character edit re-translated the whole reply). The cache keeps up to 4000 paragraphs within 2,000,000 characters, least recently used first out, and paragraphs reused from it get a fresh timestamp; the in-memory copy keeps 1200 and pruning runs every 128 written paragraphs. When the cache fills part of a reply, the start notice and progress label say how many changed paragraphs are sent again ("바뀐 문단 n개만 다시 번역"), or how many remaining paragraphs a resumed batch sends; nothing to send means no start notice. Numbered-batch fallbacks are unchanged.

Modified 2026-10-20 (Blue Lemonade 7.4.0): requests now carry a usage purpose for the request log and the usage ledger: the arrow re-translation (correction) is tagged as a re-translation and outgoing-text translation as input translation, separately from chat translation. Nothing is sent anywhere new; the tags stay on this device.

Modified 2026-10-20 (2.9.9): leftover-fix.js leftoverHan also picks a single Han character glued to the end of a Hangul word (「변顔」 from 変顔, followed by a space or punctuation) when that character came from a Japanese or Chinese source line, so the automatic leftover-line retranslation repairs it; characters absent from the source or present in a Korean source line are left as before.
