# LLM Translator — Blue Lemonade integration

Modified 2026-09-24. Based on the existing local 2.1.6 modification of https://github.com/NamelessKkang/llm-translator-custom (original: https://github.com/1234anon/llm-translator). Original AGPL-3.0 LICENSE retained. Host import paths and asset loading adapted; one settings view can appear in the extension drawer or Blue Lemonade; existing storage keys retained.
Modified 2026-10-10 (2.3.0): added translateForSpeech / speechReady / speechModelTag to the Blue Lemonade translator API (speech-translate.js, glossaryLinesFor) so the bundled TTS add-on can read lines in a chosen listening language with this translator's connection; chat translation behaviour unchanged.
Modified 2026-10-10 (2.3.1): translation-segments.js remembers the source-echo comparison key of each text for the rest of the current task (cleared on the next microtask), so end-of-reply echo checks no longer re-normalise the same paragraphs and sentences; results unchanged.
Modified 2026-10-12: protected blocks registered at runtime through the Blue Lemonade translator API (protect / unprotect, memory only, appended after the user's protected-text rules) are never sent to the model and are kept in place once; a protected block whose placeholder the model drops is put back at its source paragraph and that result is not cached; fold views show such blocks only on the translated side; a queued auto translation whose message text changed during the short wait is translated with the current text instead of being skipped; a document event llm-translator:rendered is sent after the translator redraws a message; reuse checks ignore protected blocks when rejecting HTML.
Modified 2026-10-13: a translation that is mostly Korean/Japanese/Chinese drops a line holding only one Latin-script word that appears nowhere in the source text (a model glitch seen as a stray place name on its own line); applied before caching, to cached rows from earlier versions, to /llmTranslate results and to stored translations when shown; a translation the user edited by hand is marked (extra.translation_edited = source hash) and left alone. Modified 2026-10-13 (6.2.5): the same filter also removes paragraph-marker debris when the source has no ⟦ ⟧ — a Latin-only aside ending in ⟧ at the start of a line, and leftover ⟦n⟧ markers.

Modified 2026-10-15: automatic incoming/outgoing translation is queued after awaited message-render and saved-swipe events and their postprocessors finish. Valid saved-swipe translations retain the existing cache skip. Nested renders of one message are coalesced; chat changes, swipe changes, failed dispatches and stopped observers discard pending work. The host emitter keeps its original return value, receiver and errors. Existing source/edit/display guards remain active from queueing onward; throttled jobs recheck their target after waiting.

Modified 2026-10-15: known prompt status/header/footer cards translate display values while preserving renderer keys, markup, hidden data and code locally. Explicit protected-text rules keep precedence. Missing, duplicated or reordered field tokens reject the result; card structures stay outside later prose cleanup and render once on the translated side of combined views. Existing cache rows whose card keys or code differ from the source are skipped during reuse without deleting stored rows; valid untranslated cards remain eligible and can be explicitly retranslated.
